# План: Мультивалютность v2 — хранение цены в исходной валюте + маркер

**Статус:** v2 и уточнение D-23b **реализованы** (код и миграция применены)
**Тип задачи:** пересмотр модели хранения/конвертации цен (v2 поверх `plan-finances.md`)
**Связанные пункты:** `plan-finances.md` (v1), `plan-2.md` §4/§5/§8/§9
**Дата:** 2026-08-21

---

## 0. Что меняется по сравнению с v1

v1 хранил **все** цены в USD-центах (целое ×100). Опытная эксплуатация выявила дрейф при round-trip:
ввод `1010 ₴` → `1010/44 ≈ 22.9545$` → округление до цента `22.95$` → вывод `22.95×44 = 1009.80 ₴`
(меньше и дробное, чем вводили). Причина: `1010/44` не имеет конечной записи, поэтому **никакая**
конечная точность хранения в USD не даёт точного возврата в исходную валюту.

**Решение v2:** хранить цену **в той валюте, в которой её задали**, плюс маркер (код) этой валюты.
При отображении в той же валюте — показываем «как есть» (без пересчёта, без дрейфа). При переключении
в другую валюту — конвертируем через USD с **максимальной точностью**, округляя **только при выводе и сохранении**.

---

## 1. Цель

1. Настройки: 4-я вкладка **«Финансы»** — список валют + валюта отображения по умолчанию (как в v1).
2. Цены хранятся **в исходной валюте** + маркер валюты (не обязательно USD).
3. Отображение: в той же валюте — без пересчёта; в другой — через USD, округление только на выводе.
4. Ввод в админке — в выбранной валюте; сохраняем «как ввели» + маркер этой валюты.
5. Агрегации (итог конфигуратора, чек) — через USD с полной точностью, округление в конце.
6. Валюта отображения по умолчанию — **гривна** (как в v1).

## 2. Текущее состояние (что затрагивается)

| Что | Где сейчас (v1) |
|---|---|
| Цены — целые рубли/USD-центы | `products.price`, `categories.workPrice`, `components.price`, `components.processingPrice`, `orders.calcPrice` |
| Отображение цен | `formatPrice()` в `lib/format.ts` |
| Жёсткие «₽» в текстах | `home`, `catalog`, `/configurator`, `Settings.about` |
| Фильтр цен каталога | `catalog/[slug]/page.tsx` — границы 2000 / 2500 ₽ |
| Вкладки настроек | `SettingsPanel.tsx` — Контакты / Тексты / Telegram / Финансы |
| Панель «Вид» | `public/js/skin-switcher.js` |
| Ввод цен в админке | `ProductModal`, `ComponentModal`, `CategoryEditor`, `NewCategoryModal` |

**v2-изменение схемы:** каждое price-поле становится составным `(priceMinor INTEGER, priceCurrency TEXT)`. Маркеры **независимы** для каждого поля — у компонента `price` и `processingPrice` могут быть в разных валютах (Q-10: деталь куплена за $, обработка мастера — за ₴):
- `products.price` + `products.priceCurrency`
- `categories.workPrice` + `categories.workPriceCurrency`
- `components.price` + `components.priceCurrency`
- `components.processingPrice` + `components.processingPriceCurrency`
- `orders.calcPrice` + `orders.calcPriceCurrency`

`priceMinor` — целое число минорных единиц (копеек) **исходной** валюты этого поля, напр. `1010 ₴` → `priceMinor=101000`, `priceCurrency="UAH"`. Каждое поле хранит свою валюту независимо.

## 3. Предлагаемые решения

| # | Вопрос | Предложение |
|---|---|---|
| D-15 | Как хранить цену | **Составное `(priceMinor, priceCurrency)`** — целое число копеек исходной валюты + код валюты. НЕ приводим к USD при сохранении. Единый формат «USD-центы» из v1 — **отклонён** (дрейф round-trip для не-USD). Целочисленные минорные единицы сохраняем, чтобы не было float при хранении/выводе в родной валюте |
| D-16 | Где хранить список валют | `Settings`: `finance.currencies` (JSON) + `finance.defaultCurrency` (код) — без изменений |
| D-17 | Доллар | Обязателен, неудаляем, `ratePerUsd = 1`; название и символ редактируемы — без изменений |
| D-18 | Направление курса и конвертация | `ratePerUsd` = сколько единиц валюты за 1 USD. Конвертация **только для отображения в ДРУГОЙ валюте**: `native→USD: value / rate(native)`; `USD→target: usdValue × rate(target)`. Промежуточные расчёты — с максимальной точностью (float допустим, т.к. округление только на выводе). Родная валюта выводится без конвертации |
| D-19 | Формат отображения | Сумма с округлением до 2 знаков + символ после числа: `1 950.00 ₴`, `2 050.00 ₽`, `21.12 $`. В родной валюте значение точное (без дроби, если вводили целое); в чужой — округление до 2 знаков на выводе. Округление — **банковское (half-up)** (Q-11) |
| D-20 | Панель «Вид» | Подпись «Вид», блок скинов + блок валют, cookie + localStorage + перезагрузка — без изменений |
| D-21 | Выбранная валюта | `localStorage` + `cookie` (SSR), перезагрузка при выборе — без изменений |
| D-22 | Стартовые курсы | USD `1`, EUR `0.92`, RUB `85`, UAH `44` — без изменений (правятся в настройках) |
| D-23 | Миграция существующих цен | Два сценария (Q-8): (а) БД ещё **не** мигрировалась v1 — исходные рубли сохраняем как `(руб×100 minor, "RUB")`, без перевода в USD; (б) v1 уже применилась (цены лежат в USD-центах) — оборачиваем в `(minor, "USD")`, повторной конвертации нет (точно, но без привязки к рублю). Те же поля: `products.price`, `categories.workPrice`, `components.price`, `components.processingPrice`, `orders.calcPrice`. `configJson` заявок не трогаем |
| D-24 | Ввод цен в админке | Каждое price-поле формы показывает значение в **текущей валюте «Вид» на момент ввода этого поля** (Q-9) и сохраняет `priceMinor = введённое×100`, `priceCurrency = код валюты в этот момент`. Маркеры независимы: мастер может ввести `price` в $ (переключив «Вид» на $), а `processingPrice` — в ₴ (переключив на ₴) — обе валюты запомнятся отдельно (Q-10). **Обратная конвертация в USD при сохранении НЕ делается** |
| D-25 | Курсы на клиенте | `GET /api/currency` → `{ currencies, default }` — без изменений |
| D-26 | Агрегация / итоги (конфигуратор, чек, дашборд) | Базовая валюта агрегации = **текущая валюта отображения пользователя** (`displayCurrency`). `sumPriced` собирает **каждое price-поле как независимый слагаемый** со своим `priceCurrency`: `category.workPrice`, и для каждого компонента — его `price` **и** `processingPrice` (маркеры независимы, Q-10). Алгоритм:<br>1. Выделить множество валют по всем слагаемым.<br>2. **Все слагаемые в одной валюте** (`size==1`): база = эта валюта, сумма `Σ priceMinor/100` напрямую, **без хода через USD**. База == `displayCurrency` → показываем как есть (точно). Иначе — однократно конвертируем итог в `displayCurrency`, округляем на выводе.<br>3. **Валюты разные** (`size>1`): конвертируем **каждое слагаемое с `priceCurrency != displayCurrency`** в `displayCurrency` (полная точность, без промежуточных округлений), совпадающие берём как есть; суммируем в `displayCurrency`; округляем только в `formatPrice`. Результат отображаем и (для заявки) фиксируем в `displayCurrency`.<br>Ключевое: никаких промежуточных округлений — только на выводе. Математически эквивалентно агрегации через USD (линейность); при одной совпадающей валюте — ноль конверсий и ноль дрейфа |
| D-27 | Удаление валюты | Удаление **не запрещается**. При попытке удалить валюту, у которой есть цены с этим `priceCurrency`, показываем предупреждение: сколько цен будет затронуто и что конвертация по всей БД **может быть небыстрой**. Если пользователь подтверждает — удаляем валюту и конвертируем все такие цены в USD: `priceMinor = round(исходник/100 / rate(code) × 100)` (полная точность расчёта, округление до USD-центов), `priceCurrency="USD"`. После конверсии показ в USD точный, в прочих валютах — через USD с округлением на выводе |
| D-23b | Границы фильтра цены каталога | Хранятся как `Priced`: `finance.filterLow`/`finance.filterHigh` = минора в валюте + `finance.filterLowCurrency`/`finance.filterHighCurrency` = код. **НЕ в USD-центах** (ранняя редакция D-23 подразумевала USD-центы — отклонено: несогласованно с v2, где все цены в нативной валюте). На вкладке «Финансы» ввод показывается и сохраняется в **текущей валюте «Вид»** (как обычные цены по D-24) — никакой конвертации в доллары при сохранении. Сравнение/сортировка в каталоге — через `toUsdAmount(Priced, finance)`, как и для цен. Исторические границы в USD-центах переводит миграция `migrate-currency-fields.ts` в рубли (rate 85) и проставляет маркер `RUB` |
| D-28 | Сравнение/фильтр цен | Границы фильтра и сортировка — через приведение к USD (полная точность), округление не нужно. Границы хранятся как `Priced` (D-23b) и сравниваются через `toUsdAmount` |

## 4. Модель данных

### 4.1 Настройки (без изменений относительно v1)

```jsonc
// finance.defaultCurrency
"UAH"

// finance.currencies
[
  { "code": "USD", "name": "Доллар", "symbol": "$",  "ratePerUsd": 1 },
  { "code": "UAH", "name": "Гривна", "symbol": "₴", "ratePerUsd": 44 },
  { "code": "RUB", "name": "Рубль",  "symbol": "₽", "ratePerUsd": 85 },
  { "code": "EUR", "name": "Евро",   "symbol": "€", "ratePerUsd": 0.92 }
]
```

### 4.2 Price-поля (v2 — составные)

```ts
// пример на products
interface Priced {
  priceMinor: number;      // целое: копейки ИСХОДНОЙ валюты (1010 ₴ → 101000)
  priceCurrency: string;   // код валюты, в которой задана цена ("UAH")
}
```

- `priceCurrency` — один из `finance.currencies`.
- `USD` допустим как маркер (цена задана в долларах) — никакой особой обработки, единообразно с остальными.
- Исторические данные после миграции (D-23) несут маркер `"RUB"`.

## 5. Шаги (после утверждения)

1. **`lib/currency.ts`** — типы `Currency`, `CurrencySettings`, `Priced`; чтение списка/дефолта из Settings;
   `usdToDisplay`, `displayToUsd` (D-18, только для чужой валюты); `formatPrice(Priced, displayCurrency)`
   (родная валюта — без пересчёта; чужая — через USD, округление на выводе, D-19); `sumPriced(Priced[], displayCurrency)`
   для агрегаций (D-26); чтение выбранной валюты из cookie/localStorage с fallback на дефолт.
2. **Настройки — таб «Финансы»** (`SettingsPanel.tsx`): таблица валют; у USD недоступен только курс;
   **поток удаления по D-27** (предупреждение о затронутых ценах + небыстрой конверсии по БД, по подтверждению — удаление валюты и пересчёт цен в USD); поле дефолтной валюты.
   Расширение `KNOWN_KEYS` ключами `finance.*`, валидация (USD неудаляем, `ratePerUsd` строго `1` у USD, `>0` у остальных).
3. **`GET /api/currency`** (публичный) — список валют + дефолт.
4. **Миграция цен** — `scripts/migrate-usd.ts`: превратить целые рубли в `(руб×100, "RUB")` (D-23, v2).
   Правка `scripts/seed.ts`: новые цены сразу составные `(minor, code)`.
5. **Отображение цен** — `formatPrice()` валютный по D-18/D-19/D-26; обход всех мест с ценой
   (`ProductCard`, карточка товара, каталог, админские таблицы, чек заявки, дашборд, `order-success`);
   итоги через `sumPriced`. Замена жёстких «₽» на вычисленные значения.
6. **Фильтр цен каталога** — границы как `Priced` (D-23b): `finance.filterLow`/`finance.filterLowCurrency` (и High). Сохраняются в текущей валюте «Вид» на вкладке «Финансы»; сравнение через `toUsdAmount` (D-28).
7. **Ввод цен в админке** — `ProductModal`, `ComponentModal`, `CategoryEditor`, `NewCategoryModal`:
   сохраняют `priceMinor` + `priceCurrency` текущей валюты формы (D-24, без конвертации в USD). Подпись валюты у полей.
8. **Панель «Вид»** — `skin-switcher.js`: подпись «Вид», блоки скинов + валют; cookie + localStorage + перезагрузка.
9. **Уведомления Telegram** — сумма в валюте отображения мастера (Q-5), итог через `sumPriced`.

**Приёмка:** ввод `1010 ₴` и просмотр в гривне даёт ровно `1 010.00 ₴` (без дрейфа); переключение на евро/рубль
даёт корректную конвертацию с округлением только на выводе; в БД цена хранится с маркером исходной валюты;
агрегации (итог конфигуратора) считаются через USD с полной точностью; удаление валюты, занятой в ценах, конвертирует их в USD после подтверждения предупреждения.
