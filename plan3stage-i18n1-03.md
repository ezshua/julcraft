# Задание агенту — i18n-1 · Шаг 3 из 12: Переключатель RU/EN/UK в панели «Вид»

**Тип задачи:** UI-механизм (vanilla JS)
**Зависимости:** i18n-1 · Шаги 1–2
**Связанные пункты плана:** `plan-3.md` §5 (D-i18n-5); `site/public/js/skin-switcher.js`

## Цель

Кнопки RU/EN/UK в панели «Вид» рядом со скином и валютой: запись cookie `julcraft-locale` + localStorage + перезагрузка — ровно по механике валюты.

## Контекст и прецедент

- `skin-switcher.js` уже расширялся под валюты (plan-finances.md D-20/D-21) — правка site-копии разрешена; `mockup/**` не трогать. Размещение языковых кнопок утверждено D-i18n-5.
- Валютные кнопки: cookie `path=/;max-age=31536000` + localStorage + `location.reload()` (skin-switcher.js ~строки 155–167) — скопировать механику один в один.

## Шаги

1. Константы: `LOCALE_KEY = 'julcraft-locale'` (cookie и localStorage — одно имя, как у валюты).
2. Блок кнопок `data-locale="ru|en|uk"` с подписями `RU/EN/UK` после блока валют (разделитель `span.ss-sep` + контейнер). Клик: если значение не текущее → cookie + localStorage + `location.reload()`. Пометка `is-on` по значению cookie (не localStorage — SSR читает cookie).
3. Подписи самой панели («Вид», `aria-label «Переключатель вида»`) — маленькая inline-карта per-locale, выбираемая по cookie при `buildBar()`. Названия скинов «06 · Тёплый» / «12 · Мемфис» — бренд-константы, не переводятся (аудит §6 п.5).
4. Фолбэк: нет cookie → `ru`, кнопка RU помечена `is-on`.

## Критерии приёмки

1. Переключение RU↔EN↔UK перезагружает страницу; выбор переживает перезагрузку и новое посещение; `<html lang>` меняется (шаг 2).
2. Вёрстка панели не изменилась кроме новых кнопок (скриншот до/после); стили кнопок — существующие (`#skin-switcher button`), новых CSS-правил не добавлять.
3. Клик по уже активному языку не перезагружает страницу (как у валюты).
4. `npm run lint`, `npm run build`.

## Не делать (out of scope)

- Перевод содержимого страниц — следующие шагы (пока переключение меняет только `lang`).
