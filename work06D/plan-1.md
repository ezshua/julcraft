## 1. Видение продукта

Сайт-витрина небольшой мастерской авторских украшений. Ключевые возможности:

1. **Витрина** — новинки и избранные изделия на главной.
2. **Каталог** — 8–12 категорий изделий (броши, кулоны, бусы, ожерелья, серьги, браслеты, кольца, комплекты и пр.).
3. **Конфигуратор** — сборка украшения из комплектующих (со склада и «под заказ») с автоматическим расчётом цены и срока изготовления, визуальный коллаж из фото комплектующих.
4. **Заявки** — оформление заявки на заказ без онлайн-оплаты (мастер связывается с клиентом сам).
5. **Админка** — самостоятельное управление каталогом, складом комплектующих и заявками владельцем мастерской.
6. **Контакты** — способы связи, карта, форма обратной связи.

### Целевая аудитория и пути пользователя

| Сценарий | Путь |
|---|---|
| Посмотреть работы | Главная → Каталог → Карточка изделия → Заявка |
| Собрать украшение | Конфигуратор → Категория → Слоты → Коллаж + расчёт → Заявка |
| Найти мастера | О мастерской / Контакты → Связь |

## 3. Технический стек

| Слой | Технология | Аргументация |
|---|---|---|
| Фреймворк | Next.js 14 (App Router) + TypeScript | SSR/SSG для SEO, API routes в одном монолите, оптимизация изображений из коробки |
| UI | Tailwind CSS + shadcn/ui | Скорость разработки, консистентный дизайн |
| Формы/валидация | React Hook Form + Zod | Единая схема валидации на клиенте и сервере |
| БД | SQLite (старт) → PostgreSQL (при росте) | Файл-БД без внешних сервисов; простой бэкап; кроссплатформенность (Win11/Linux) |
| ORM | Drizzle ORM | Типобезопасность, миграции, лёгкий переход SQLite→Postgres |
| Авторизация админки | Auth.js (Credentials + JWT), один пользователь | Минимальная сложность |
| Изображения | next/image + sharp; загрузка в `/public/uploads` | Оптимизация и серверная сборка коллажа |
| Canvas-коллаж | react-konva (или fabric.js — выбрать на этапе 5) | Drag&drop, зум, экспорт в PNG |
| Уведомления | Telegram Bot API (основной) + Nodemailer (fallback) | Telegram — удобный канал для мастерской |
| Процесс-менеджер | PM2 + Nginx (VPS) | Стандарт для Node на Ubuntu |

## 6. Конфигуратор — логика (ключевая фича)

### UX-поток
1. Выбор категории → загрузка SlotTemplate'ов и компонентов (isActive && (stockQty>0 || isOrderable)).
2. Split-view: слева canvas-коллаж, справа список слотов; в каждом слоте — карточки компонентов (фото, цена, наличие, срок «под заказ»), выбор qty в пределах min/max слота.
3. Коллаж: авторазмещение в сетку по слотам → пользователь может двигать, масштабировать, удалять элементы.
4. Живой расчёт (пересчёт при каждом изменении):

```
ЦЕНА  = category.workPrice
      + Σ(component.price × qty)
      + Σ(component.processingPrice × qty)

СРОК  = category.baseWorkDays
      + Σ(component.processingDays × qty)        // поправка на количество/обработку
      + max(deliveryDays среди выбранных "под заказ", иначе 0)
```
(Точные формулы — см. Открытый вопрос Q-6.)

5. Форма заявки: имя, контакт, комментарий → POST /api/orders:
   - серверная валидация (Zod): слоты заполнены в пределах min/max, компоненты доступны;
   - пересчёт цены/срока на сервере (не доверяем клиенту);
   - экспорт canvas-данных → серверная генерация PNG (sharp) → `/public/uploads/collages/`;
   - запись Order со snapshot конфигурации;
   - Telegram-уведомление мастеру (фото коллажа + детали заявки).

## 9. Риски и компромиссы

| Риск | Митигация |
|---|---|
| SQLite — потолок при росте нагрузки | Drizzle упрощает миграцию на PostgreSQL; решение принято осознанно |
| Качество коллажа зависит от фото комплектующих | Требование в админке: PNG на прозрачном/белом фоне, единый ракурс |
| Win11 (демо) vs Linux (прод) | Кроссплатформенный стек; различия только в env и путях — вынести в конфиг |
| Размазывание scope (корзина, оплата, кабинет) | Жёстко следовать §2 «Решения»; новые хотелки — в backlog ниже |

### Backlog (после MVP, не входит в план)
Онлайн-оплата, корзина, личный кабинет, отслеживание заказа клиентом, 3D-конфигуратор, многоязычность.
