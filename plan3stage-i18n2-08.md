# Задание агенту — i18n-2 · Шаг 8 из 8: SEO-автогенерация транслитом EN (товары/категории)

**Тип задачи:** логика SEO
**Зависимости:** i18n-2 · Шаги 1–6 (данные в {ru,...}), i18n-1 · Шаг 11 (словарь meta)
**Связанные пункты плана:** `plan-3.md` §5 D-i18n-2/D-i18n-7; TRANSLIT-таблица — `lib/format.ts` `slugify()`
**Файлы зоны:** `app/(public)/product/[slug]/page.tsx`, `app/(public)/catalog/[slug]/page.tsx` (generateMetadata), возможно `lib/seo`-helper при его наличии

## Цель

Автогенерация SEO товаров/категорий работает по правилу D-i18n-2: ручной ввод хранится как введён; если SEO-полей нет — автогенерация: для RU — текущее поведение (RU-шаблон из названия), для EN — транслит названия + EN-шаблон («Brooch «...» — JulCraft»), для UK — RU-фолбэк (или UK-шаблон, если словарь есть — решение в отчёте).

## Шаги

1. Найти текущую логику фолбэка SEO (если metaTitle пуст → генерация из name). Зафиксировать в отчёте, где она живёт.
2. В `generateMetadata`: locale-aware фолбэк-цепочка — `L(metaTitle, locale)` (ручной) → автогенерация per-locale (шаблоны из словаря `meta.*`, название через `L(name, locale)`; EN-транслит названия — `slugify`-таблица из `lib/format.ts` — при EN-названии «Brooch Romashka» slug уже латиница, `slugify` проходит без изменений).
3. Slug URL не переводится (D-i18n-2: без URL per-языка — URL остаются текущими, RU-транслит).
4. RU-сверка: SEO всех товаров/категорий без ручного ввода — те же строки, что раньше.

## Критерии приёмки

1. RU: автогенерация SEO идентична прежней (сверка `<title>` нескольких товаров/категорий).
2. EN: товар без ручного SEO отдаёт EN-шаблон с транслитом; товар с ручным EN-вводом — как введён.
3. URL не изменились (sitemap/страницы открываются по старым адресам).
4. Grep зоны; `npm run lint`, `npm run build`.

## Не делать (out of scope)

- sitemap/hreflang (i18n-6), словарь мета категорий — уже в i18n-1 шаг 11 (если не хватит ключей — добавить сюда же).
