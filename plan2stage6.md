## Золотые правила (§0 плана) — обязательны

2. **Никакого хардкода редактируемых данных** (решение руководителя от 2026-08-25): подписи/тексты для метаданных брать из БД (`Settings`, категории, товары), не заводить новых статичных карт контента.

4. Файлы `mockup/**` не редактировать. Коммиты — только по явной команде руководителя.

## Решения руководителя (зафиксировано 2026-08-26, перед стартом этапа)

1. **Base URL для SEO — через env-переменную.** Добавить `SITE_URL` в `.env.example`; `metadataBase`, OG-URL и `sitemap.xml` строятся от неё. Fallback в dev — `http://localhost:3000`. Реальный домен будет вписан при деплое (Этап 7).
2. **Изображения товаров — скачаться локально.** Скачать фото Unsplash из seed в `site/public/uploads/products/`, в БД писать локальные пути `/uploads/products/<файл>` — так, как будто их загрузил пользователь через админку (`/api/upload` пишет именно такие пути). Никаких `remotePatterns` для внешних хостов не настраивать. Файлы коммитятся в репозиторий (как уже сделано с SVG комплектующих в `public/uploads/components/`).
3. **Lighthouse ≥ 90 принимается локально**: `npm run build && npm run start`, прогон Lighthouse в Chrome по `http://localhost:3000`. Результаты (цифры по категориям Performance/SEO/Best Practices/Accessibility, mobile) — в отчёт.
4. **Состояния — по всем значимым маршрутам** (выбор в пользу скорости восприятия): `error.tsx` для публичной части и админки, `loading.tsx` для остальных тяжёлых маршрутов — по образцам макета.
5. **SEO-поля товара из админки включить в `generateMetadata`** (расширение буквы T-6.2: поля `metaTitle/metaDescription/ogImage` уже хранятся и редактируются, но не используются метаданными). OG/description — не только у товара, но и у остальных публичных страниц.
