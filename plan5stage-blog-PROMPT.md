Подставь номер этапа вместо `{{N}}`. Для направления 5 это числа **2…8**.
Этапы 0 и 1 выполнены.

```text
Задача: выполнить этап {{N}} направления «Блог мастера» в репозитории C:\alexx\Src\julcraft.

ЧТО ПРОЧИТАТЬ ДО НАЧАЛА РАБОТЫ (по порядку, без исключений):
1. plan-5-blog.md — решения B1–B8 и D-B1…D-B15, модель данных, API, инварианты.
2. plan5stages-blog.md — карта этапов и зависимости.
3. plan5stage-blog-{{N}}.md — ТВОЁ задание: зона файлов, шаги, критерии приёмки, «не делать».
4. Макеты из mockup/, перечисленные в задании, — макет источник истины.
5. site/AGENTS.md — перед кодом маршрутов прочитать гайды из
   site/node_modules/next/dist/docs/01-app/01-getting-started/ (это версия Next 16,
   отличается от учебных материалов).

ОБЯЗАТЕЛЬНЫЕ ПРАВИЛА ПРОЕКТА:
- Макет — источник истины. Чего нет в макете — вопрос руководителю, а не своё решение.
- Живая БД site/julcraft.db не пересиживать. Перед db:migrate — копия файла.
  db:seed запускать только с DATABASE_URL, переопределённым на временную БД.
- Порядок для чистой БД: db:migrate → db:migrate-currency → db:migrate-locale → db:seed.
- Ключи интерфейса добавлять сразу в lib/dictionaries/ru.ts, en.ts и uk.ts.
- Новые зависимости — только react-markdown и remark-gfm (решение B3). Других не ставить.
- Публичные выборки записей идут только через публичные функции site/lib/blog.ts.
  Прямых db.select() по blogPosts в публичных страницах не делать.
- Коммит не делать без явной команды руководителя.

ОСОБЕННОСТИ ОКРУЖЕНИЯ (иначе команды падают):
- tsx, eslint, next build и npm из файловой песочницы не стартуют: esbuild и next
  порождают процессы через named pipe → EPERM. Запускай такие команды с расширенным
  доступом, объяснив пользователю причину.
- npm install не работает: кэш npm в AppData\Local\npm-cache закрыт. Новые пакеты
  устанавливает руководитель — на этапе 2 их нужно установить ДО начала работы.

  Это ошибки, существовавшие до блога: не чинить и не считать своим провалом.
  Свои файлы проверять отдельно — они должны быть чистыми.

ПОРЯДОК РАБОТЫ:
1. Прочитай задание этапа и кратко перечисли, что понял и что будешь делать.
2. Реализуй по шагам задания, не выходя за «Файлы зоны».
3. Прогони приёмку своего этапа плюс npm run check:i18n, npm run lint, npm run build.
4. Дай отчёт: сделано по пунктам, создано/изменено (пути), результат проверок,
   отклонения от задания и почему, открытые вопросы. Коммит не делай.
```
