# Задание агенту — i18n-2 · Шаг 3 из 8: Вывод через L() — категории и слоты

**Тип задачи:** замена вывода
**Зависимости:** i18n-2 · Шаги 1–2
**Связанные пункты плана:** `plan-3.md` §4 (вывод с фолбэком locale → ru)
**Файлы зоны:** `app/(public)/catalog/**` (названия категорий), `app/(public)/configurator/**` (названия категорий + слотов), `components/configurator/ConfiguratorClient.tsx` (вин. падеж — см. i18n-1 шаг 8), `app/(public)/page.tsx` (плитка категорий), соответствующие SEO-выводы (только отображаемые, не автогенерацию — шаг 8)

## Цель

Названия категорий и слотов рендерятся через `L(value, locale)`. RU-вывод не меняется (фолбэк ru). Словарь винительного падежа из словаря i18n-1 уже per-locale — сопоставление slug → ключ словаря.

## Шаги

1. Во всех местах вывода `category.name`, `slot.name` → `L(category.name, locale)` (server-компоненты получают locale через `getLocale()`; client — уже имеют срез словаря, добавить данные через props как раньше).
2. SEO-вывод «ручной ввод как есть» (D-i18n-2): `generateMetadata` категорий показывает `L(metaTitle, locale)` — вручную введённый EN-текст хранится как введён, фолбэк — ru. **Не путать с автогенерацией** (шаг 8).
3. Словарь вин. падежа: slug → словарь per-locale (ru-вин., en, uk) — уже сделан в i18n-1 шаг 8; здесь подключить названия категорий: `Собираем {L(name, locale) в вин. падеже для ru / просто name для en/uk}`.
4. Прогнать RU-сверку: витрина категорий, конфигуратор (обзор + [slug]), крошки, SEO категорий.

## Критерии приёмки

1. RU: названия категорий/слотов везде те же, что до шага (сверка страниц).
2. EN/UK: если в БД появятся `{ru, en}`-значения (вручную в dev-БД для проверки), витрина показывает en при переключении; без en — фолбэк ru (проверить оба).
3. Grep зоны — новые вызовы `L(` на месте хардкода; `npm run lint`, `npm run build`.

## Не делать (out of scope)

- Товары (шаг 4), комплектующие (шаг 5), Settings (шаг 6), поля админки (шаг 7).
