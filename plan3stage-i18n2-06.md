# Задание агенту — i18n-2 · Шаг 6 из 8: Вывод через L() — Settings-тексты

**Тип задачи:** замена вывода
**Зависимости:** i18n-2 · Шаги 1–2
**Связанные пункты плана:** `plan-3.md` §4; `plan-3-i18n-constants.md` §4 (lib/settings.ts), §5
**Файлы зоны:** `lib/settings.ts` (дефолты), `lib/get-settings.ts`, все места вывода Settings-текстов на витрине: чек знакомства (главная + about), принципы (about), часы/адрес (Footer, Contacts, not-found, MobileMenu), подпись thanks (order-success)

## Цель

Settings-тексты (чек, принципы, часы, адрес, история, thanks) — через `L(value, locale)` на витрине. Дефолты `lib/settings.ts` — в формате `{ru: ...}`.

## Шаги

1. `lib/settings.ts`: все текстовые дефолты → `{ru: "..."}` (значения те же). Часы («выходной», интервалы) — тоже локализуемые строки (выходной — ключ словаря; интервалы — как есть).
2. `lib/get-settings.ts` / потребители: значения считываются как LocalizedString, вывод через `L(...)` в компонентах витрины (Footer, HoursBoard, Contacts, about, чек знакомства, order-success thanks).
3. Адрес: используется в MobileMenu/Footer/Contacts/not-found/map-title — все места вывода через `L`. (Сам адрес — контент, EN-версия появится через админку/сид — i18n-5.)
4. RU-сверка всех мест вывода.

## Критерии приёмки

1. RU: чек, принципы, часы, адрес, thanks — тексты те же (главная, about, футер, контакты, чек заявки, 404).
2. EN/UK: вручную проставленный в dev-БД `about.short.en` показывает EN-версию; без — фолбэк ru.
3. Grep зоны; `npm run lint`, `npm run build`.

## Не делать (out of scope)

- Поля EN/UK в админ-панели Settings (шаг 7 — модалки) и i18n-4 (SettingsPanel), переводы дефолтов (i18n-5).
