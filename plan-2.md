## 0. Как работать с этим файлом

- Каждая задача имеет ID (`T-x.y`), чекбокс и критерии приёмки. ИИ-агенты берут задачи по ID и отмечают выполнение.
- Раздел «Решения» фиксирует принятые решения — менять только через обсуждение с руководителем, с записью в «Журнал изменений».
- Раздел «Открытые вопросы» — блокеры, требующие ответа владельца продукта. Каждый вопрос содержит предлагаемые варианты.
- Журнал изменений — в конце файла.

### Золотые правила (обязательны для всех агентов)

1. **Макет `mockup/` — источник истины.** Заказчик утвердил именно его. Всё, что есть в макете, переносится на сайт **копированием 1:1**: HTML-структура, CSS-классы, тексты, иконки (inline-SVG), состояния, модалки, разметка страниц.
2. **Запрещено** (это ошибка первой итерации): переделывать вёрстку макета, придумывать свои компоненты/дизайн/тексты/поля, «улучшать» одобренное.
3. **Если чего-то нет в макете — не додумывать.** Остановиться, записать вопрос в §9 «Открытые вопросы» с вариантами решения, продолжить несвязанные задачи. Блокирующую задачу не закрывать до ответа.
4. **Приёмка страницы** = сравнение с её файлом макета: совпадение структуры и классов, визуальная идентичность. Не «похоже», а «копия + данные из БД». Отклонение от макета — только через решение в журнале.
5. **Статичные демо-блоки макета** (например, «демо пустого состояния», «демо скелетона» на category.html) — это компоненты для реальных состояний сайта, а не декорации.

## 1. Видение продукта

Сайт-витрина небольшой мастерской авторских украшений (см. макет: «эст. 1976», винтажная бижутерия, всё в одном экземпляре). Ключевые возможности:

1. **Витрина** — новинки и избранное на главной (12 изделий на полке).
2. **Каталог** — 10 категорий (Броши, Кулоны, Серьги, Кольца, Браслеты, Бусы и ожерелья, Комплекты, Клипсы и манжеты, Винтажный ремонт, Амулеты и подвески).
3. **Конфигуратор** — сборка украшения по слотам из комплектующих со склада («в наличии» и «под заказ») с коллажем, расчётом цены и срока; заявка без оплаты.
4. **Заявки** — без онлайн-оплаты, мастер связывается сам («без предоплаты — цена и срок в чеке после звонка»).
5. **Админка** — «панель мастера»: товары, склад, категории+слоты, заявки, настройки.
6. **Контакты** — форма обратной связи, карта, часы, соцсети.
7. **Винтажный ремонт** — услуга без шаблона конфигуратора; заявки через форму на контактах (как в макете).

Пути пользователя — как в макете (крошки, CTA, модалки): Главная → Каталог → Карточка → Заявка; Конфигуратор → Категория → Слоты → Коллаж+расчёт → Заявка; О мастерской / Контакты → Связь.

## 3. Решения (зафиксировано в обсуждении)

| # | Вопрос | Решение |
|---|---|---|
| D-1 | Продажи | Заявка на заказ БЕЗ онлайн-оплаты (макет: «без предоплаты — цена и срок в чеке после звонка») |
| D-2 | Стилизация | Копия CSS макета как есть: оба скина (`style-memphis.css` + `style.css`) + `skin-switcher.js`; Tailwind/shadcn/ui НЕ используются |
| D-3 | Коллаж | Клиентский: react-konva (авторазмещение + drag/зум/удаление) → `canvas.toDataURL()` PNG → сервер сохраняет в `/public/uploads/collages/`. Пометки «sharp» в макете админки — устаревшие, игнорировать |
| D-4 | Расчёт цены | `ЦЕНА = category.workPrice + Σ(component.price × qty) + Σ(component.processingPrice × qty)` (подтверждено breakdown в макете: «Работа: 1 000 ₽ + Компоненты: 1 540 ₽») |
| D-5 | Расчёт срока | `СРОК = category.baseWorkDays + Σ(component.processingDays × qty) + max(deliveryDays среди выбранных «под заказ»)`, иначе 0 (подтверждено: «База 3 дн + обработка 1 дн + доставка 0 дн») |
| D-6 | Категории | 10 из макета; «Винтажный ремонт» — без шаблона слотов (в конфигураторе disabled, заявка через форму на контактах) |
| D-7 | Контент | Все тексты, контакты, часы, соцсети — копия макета; хранятся в Settings (`contacts.*`, `about.*`), значения по умолчанию = из макета |
| D-8 | Статусы заявок | `new / in_progress / done / cancelled` — бейджи из дизайн-системы (tag--new, tag--in_progress, tag--done, tag--cancelled) |
| D-9 | «Собрать похожий →» | Ведёт в `/configurator/[categorySlug]` категории текущего товара (без предзаполнения) |
| D-10 | Выручка дашборда | Σ `calcPrice` заявок со статусом `done` за период (неделя) |
| D-11 | Seed-данные | Наполнение БД = копия демо-контента макета (товары, комплектующие, тексты, контакты); при расхождении цифр в макете источник — публичные страницы (конфигуратор: Кулоны «работа от 1 000 ₽ · 3 дн», а не 1 400 ₽ из админ-макета); дальнейшее наполнение/правки — через админку |
| D-12 | Авторизация | Один аккаунт (макет: «один аккаунт · никакой рекламы»); логин/пароль из env, не из кода |
| D-13 | Наличие товара в админке | В модалку товара добавляется select «Наличие» (в наличии / резерв / под заказ / нет на складе) + поля «резерв до» и «дней под заказ» — расширение формы без изменения вёрстки макета (Q-1, решение заказчика) |
| D-14 | Форма обратной связи | Сообщения с /contacts пишутся в Order с type=`contact` (бейдж «контакт» в таблице заявок) + уведомление мастеру (Q-2, решение заказчика) |

## 4. Технический стек

| Слой | Технология | Аргументация |
|---|---|---|
| Фреймворк | Next.js (App Router, актуальная стабильная) + TypeScript | SSR/SSG, API routes в одном монолите |
| Стили | Копия `style-memphis.css` + `style.css` + `skin-switcher.js` | Решение D-2; нулевой риск дрейфа от макета |
| БД | SQLite (старт) → PostgreSQL (при росте) | Файл-БД без внешних сервисов; лёгкий бэкап |
| ORM | Drizzle ORM | Типобезопасность, миграции |
| Авторизация админки | Auth.js (Credentials + JWT), один пользователь | Минимальная сложность |
| Изображения | next/image; загрузка в `/public/uploads` | Фото товаров; PNG комплектующих для коллажа |
| Canvas-коллаж | react-konva | Drag&drop, зум, экспорт PNG (D-3) |
| Уведомления | Telegram Bot API (основной) + Nodemailer (fallback) | В настройках макета: «Email — запасной канал» |
| Процесс-менеджер | PM2 + Nginx (VPS) | Стандарт для Node на Ubuntu |

### Структура проекта

```
site/
  app/                 # роутинг (App Router)
    (public)/          # публичные страницы
    admin/             # админка
    api/               # API routes
  components/          # UI-компоненты (скопированная вёрстка макета)
  lib/                 # db, auth, utils, calc, telegram, images
  drizzle/             # схема БД + миграции
  public/
    uploads/           # загруженные изображения и коллажи
    css/               # style-memphis.css, style.css (копии)
    js/                # skin-switcher.js (копия)
  scripts/             # seed-скрипты
  mockup/              # исходный макет (источник истины, не редактировать)
  plan-2.md            # этот файл
```

## 7. Конфигуратор — логика (ключевая фича)

### UX-поток (из макета, 1:1)
1. `/configurator` — выбор категории (только с `hasSlotTemplate`); «Винтажный ремонт» — карточка disabled с подписью «нет шаблона слотов — это услуга».
2. `/configurator/[slug]` — split-view: слева канвас-коллаж, справа аккордеон слотов. В слоте — карточки комплектующих (компоненты с `isActive=true && (stockQty>0 || isOrderable)`): фото, цена + обработка, бейдж наличия / «под заказ · N дн», stepper qty в пределах min/max слота.
3. Коллаж: авторазмещение в сетку по слотам (дефолтные позиции — как `.placed` в макете), затем drag/зум/удаление (react-konva).
4. Живой расчёт по D-4/D-5 с breakdown строками, как в макете («Работа: … + Компоненты: …»; «База … дн + обработка … дн + доставка … дн»). На ≤820px калькулятор фиксируется снизу (CSS макета уже делает это).
5. Модалка заявки: имя, контакт, комментарий → POST `/api/orders`: клиент отдаёт `canvas.toDataURL()` → сервер сохраняет PNG, пересчитывает цену/срок, пишет Order со snapshot конфигурации, шлёт уведомление → редирект на `/order-success`.

## 10. Риски и компромиссы

| Риск | Митигация |
|---|---|
| Дрейф от макета (агент начинает «улучшать» — ошибка итерации 1) | Золотые правила §0, приёмка по diff с макетом, запрет новых решений без журнала |
| Оба скина в проде (двойной объём CSS) | Копия файлов без изменений; переключатель уже работает в макете и покрыт тестом приёма |
| Расхождения демо-данных в макете (например, работа «Кулоны» 1 000 vs 1 400 ₽) | D-11: источник — публичные страницы; правки через админку |
| SQLite — потолок при росте нагрузки | Drizzle упрощает миграцию на PostgreSQL; решение осознанное |
| Win11 (демо) vs Linux (прод) | Кроссплатформенный стек; различия в env/путях — в конфиг |
| Размазывание scope (оплата, корзина, кабинет) | Жёстко следовать §3; новые хотелки — в backlog |

### Backlog (после MVP, не входит в план)
Онлайн-оплата, корзина, личный кабинет, отслеживание заказа клиентом, 3D-конфигуратор, многоязычность, состав изделия из комплектующих (ProductComponent).
