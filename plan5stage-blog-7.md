# Задание агенту — blog · 7: Админка — редактор записи

**Тип задачи:** админский интерфейс (клиентский)
**Зависимости:** blog · 2, blog · 6
**Связанные пункты плана:** `plan-5-blog.md` §6, §7, §9; D-B4, D-B7, D-B9, D-B14; решения B4, B5
**Файлы зоны:** `site/app/admin/(panel)/blog/new/page.tsx`, `site/app/admin/(panel)/blog/[id]/page.tsx`, `site/components/admin/BlogEditor.tsx`, `site/components/admin/MarkdownField.tsx`, `site/public/css/{style,style-memphis}.css`

## Общие правила

- Вёрстка 1:1 из `mockup/admin/blog-editor.html`; новые правила CSS — в конец обоих скинов.
- Редактор — **отдельная страница**, не модалка (D-B7).
- Предпросмотр — **тот же** `MarkdownBody`, что и витрина (D-B4).
- Паттерн несохранённых правок — как в `ProductModal` (`isDirty`, снимок формы, `beforeunload`, подтверждение на «Отмена»).
- Тексты ошибок берутся из ответа API — они уже локализованы.

## Задания

**7.1** Маршруты `new/page.tsx` и `[id]/page.tsx` — оба рендерят `BlogEditor`; второй при неверном id вызывает `notFound()`. Защита — в layout панели.

**7.2** `site/components/admin/BlogEditor.tsx`:
- состояние формы: локализованные `title`, `slug`, `excerpt`, `content`, `coverImage`, `metaTitle`, `metaDescription`, `tagIds`, `status`, `publishedAt`;
- `isDirty` по снимку; предупреждение при уходе;
- «Slug» — автогенерация из RU-заголовка через `slugify()` (только пока поле не правили руками) + подсказка формата;
- «Обложка» — `ImageUploader` с `kind="blog"`, превью и очистка;
- SEO-секция;
- кнопки: Сохранить (disabled, если не dirty и не новая запись), Опубликовать / Снять с публикации (по текущему статусу), Удалить (с `confirm()`).

**7.3** `site/components/admin/MarkdownField.tsx`:
- вкладки RU/EN/UK, начальная — по локали админки (как в `LocalizedField`);
- `textarea` + панель кнопок: Жирный, Курсив, Зачёркнутый, H2, H3, Цитата, Маркеры, Нумерация, Задача, Таблица, Ссылка, Картинка, Код, Разделитель;
- вставка вокруг выделения или по позиции курсора; логика — чистыми функциями `wrapSelection()`, `prefixLines()`, `insertTable()` рядом с компонентом (чтобы покрыть тестом без DOM);
- две колонки: Текст и Предпросмотр (`MarkdownBody`), на узких экранах — переключатель;
- счётчик символов.

**7.4** Вставка картинки: загрузить через `ImageUploader` или выбрать из списка `GET /api/admin/blog/media`; вставляется `![alt](/uploads/blog/файл)` в позицию курсора.

**7.5** Выбор тегов: чипы активных тегов с переключением + поле «новый тег» (создание через `POST /api/admin/blog/tags`); `tagIds` уходит в `PUT`.

**7.6** Сохранение и публикация: новая запись — `POST` и переход на `/admin/blog/<id>`; существующая — `PUT`; «Опубликовать» — `PUT` (если dirty) и затем `POST .../publish`, после чего `router.refresh()` и возврат к списку.

**7.7** Стили редактора — копией из макета в оба скина.

## Критерии приёмки

1. Правка текста видна в предпросмотре сразу; предпросмотр совпадает с витриной на одном и том же тексте.
2. Загрузка картинки и вставка её в текст работают; картинка видна в предпросмотре и на витрине.
3. Теги выбираются, создаются и сохраняются.
4. Публикация открывает `/blog/<slug>`; снятие с публикации убирает запись с витрины.
5. Несохранённые правки: Сохранить disabled, предупреждение при уходе.
6. Вкладки EN/UK сохраняются и показываются на витрине.
7. `npm run check:i18n`, `lint`, `build` — зелёные.

## Не делать

- Не добавлять автосохранение черновиков и не вводить отложенную публикацию (вне v1).
- Не использовать WYSIWYG — только markdown (решение B3).
