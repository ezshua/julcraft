# Задание агенту — i18n-2 · Шаг 7 из 8: Поля EN/UK в админ-модалках

**Тип задачи:** расширение форм (без изменения вёрстки)
**Зависимости:** i18n-2 · Шаги 1–6
**Связанные пункты плана:** `plan-3.md` §4 (поля EN/UK в модалках по аналогии с D-13); прецедент — plan-finances.md D-13 (валюта в модалке товара)
**Файлы зоны (по одной модалке за шаг — см. ниже разбивку):** `components/admin/CategoryEditor.tsx` + `NewCategoryModal.tsx`, `ComponentModal.tsx` + `ComponentTypesManager.tsx`, `ProductModal.tsx`, `SettingsPanel.tsx` (только поля, не переводы — i18n-4)

## Цель

Мастер может вводить EN/UK-значения текстовых полей контента. Расширение — UI-слова админки остаются на русском (i18n-4), добавляются только поля/инпуты «EN»/«UK» рядом с существующими (аналог D-13: валюта цены в модалке товара добавлялась без переделки вёрстки).

## Разбивка на мини-шаги (можно 4 отдельных сессии)

- 7a. `CategoryEditor` + `NewCategoryModal`: поля Название, Описание, (+ SEO-поля при их наличии) — по паре инпутов RU/EN/UK (RU — существующий инпут, EN/UK — дополнительные).
- 7b. `ComponentModal` + `ComponentTypesManager`: Название (+ название типа).
- 7c. `ProductModal`: Название, Описание, metaTitle/metaDescription (вкладка SEO).
- 7d. `SettingsPanel`: текстовые поля (чек, принципы, история, адрес, thanks) — EN/UK-инпуты.

Каждый мини-шаг автономен: свои файлы, своя приёмка.

## Шаги (общие для каждой модалки)

1. Форма: под существующим полем (или рядом, без ломки вёрстки) — инпуты «EN»/«UK» (label-суффикс). Пустое EN/UK → сохраняется только ru (не писать пустых строк).
2. Submit: значение собирается в `{ru, en?, uk?}` (ru — из основного инпута) и уходит в API. API + zod: приём `localizedStringSchema` (шаг 1) — write-путь пропускает оба формата; при чтении отдаёт как есть.
3. Валидация: RU-поле обязательно как раньше; EN/UK — опциональны.
4. Открытие модалки на существующих данных: legacy-строка → RU-инпут заполнен, EN/UK пусты; объект — три инпута.
5. Существующие списки админки (таблицы) продолжают показывать `L(value, "ru")` — RU-админка визуально не меняется.

## Критерии приёмки (per мини-шаг)

1. RU-админка: открытие/редактирование/сохранение сущности без EN/UK — поведение и вид как раньше (сверка).
2. Ввод EN (+UK) → сохранение → повторное открытие: поля на месте; витрина в EN-режиме показывает EN-значение, RU-режим — RU.
3. Пустые EN/UK не сохраняются как пустые строки (в БД отсутствуют ключи).
4. Grep зоны; `npm run lint`, `npm run build`.

## Не делать (out of scope)

- Перевод UI админки — i18n-4. Слоты (`slotTemplates`) редактируются внутри CategoryEditor — включить в 7a. Таблицы списков не переводим.
