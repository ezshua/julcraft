**Тип задачи:** вынос строк в словарь (серверный слой)

**Связанные пункты плана:** `plan-3-i18n-constants.md` §3.1 (публичные роуты), §3.3 (zod), §4 (`lib/order-status-labels.ts`, `lib/format.ts` дни недели)
**Файлы зоны:** `api/contact/route.ts`, `api/orders/route.ts`, `api/upload/route.ts`, `lib/schemas.ts` (публичная часть), `lib/order-status-labels.ts`, `lib/format.ts` (SHORT_DAYS/FULL_DAYS)

## Цель

Сообщения об ошибках, видимые гостю, — на словаре (namespace `api` + `common`), лейблы статусов и дни недели — per-locale. Telegram-шаблоны (мастер — русскоязычный) НЕ переводятся.

## Как локализовать серверные сообщения

- API-роут читает locale из cookie `julcraft-locale` тем же `getLocale()` (запросы идут из форм витрины — cookie есть). Zod-схемы: сообщения через словарь → оставить синхронные zod-схемы, но `message` подставлять из словаря per-locale (фабрика `makeSchemas(dict)` или message-карта при выводе). Выбрать менее инвазивный вариант, зафиксировать в отчёте.
- `order-status-labels.ts` → `getOrderStatusLabels(locale)` (используется и в витрине — чек заявки, и в админке — i18n-4).
- `lib/format.ts`: `reserveDayShort/reserveDayFull` → принимают locale (дни из словаря), вызовы из Avail/дашборда обновить (дашборд — i18n-4, там оставить RU-вызов).

## Критерии приёмки

1. RU: отправка заявки/сообщения с ошибочными данными показывает те же тексты, что раньше (проверить: пустые поля, кривой JSON, несуществующий товар/категория/компонент, оversайз-коллаж).
2. EN/UK: те же ошибки на выбранном языке.
3. Telegram-шаблоны не изменились (grep «[telegram» в orders/contact роутах).
4. Grep зоны — 0 кириллицы вне комментариев (кроме Telegram-блока и админских частей схем); `check:i18n`; `npm run lint`, `npm run build`.
